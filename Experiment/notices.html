Optional example encoder

EmbeddingGemma 300M Q4 ONNX conversion, revision 5090578d9565bb06545b4552f76e6bc2c93e4a66, is a separate consented download under the Gemma Terms of Use and Prohibited Use Policy. Original model: Google DeepMind; conversion: ONNX Community, pinned source. Q4 identifies the conversion's quantisation; this distribution does not claim it is a QAT model.

The optional encoder runs through Transformers.js 3.8.1 (Apache-2.0) and ONNX Runtime Web 1.22.0-dev.20250409-89f8206ba4 (MIT), using one CPU WebAssembly thread. It uses the model's 768-value sentence projection, reduced and normalised to 256 values, with a 128-token processing limit. It ranks examples and existing graph reference documents; it cannot establish reference identity, interpret or verify the player's claim. Source/revision-bound graph vectors can be inspected locally.

Included optional runtime notices: Transformers.js license · ONNX Runtime license · ONNX third-party notices · artifact and source record. Upstream sources: Transformers.js and ONNX Runtime.

Without the optional encoder, fixed and words-only examples remain available. The recommended encoder is selected during installation and can be deselected. Semantic selection adds 241,256,460 bytes of assets and needs about 488 MB of remaining quota at a fresh installation check, including staging and headroom. Extra working memory is also needed. No speed improvement, physical-mobile certification or numeric RAM minimum is established for this optional stack. See installation, mode and privacy instructions.

Example corpus and learning views

The original English example corpus contains 84 examples across 28 reasoning approaches and three authored response profiles. It is agent-reviewed; human review is pending. Source references acknowledge conceptual frameworks, not endorsement. Profile names describe scripts rather than a learner's ability or identity. Mistaken reasoning is represented faithfully and discussed separately; example claims are not proof certificates or scenario facts.

Dynamic selection changes at most one optional demonstration in eligible named-scenario prompts. Mandatory negation and unsupported-concept examples remain fixed. Two Guards, exact/narrowed interpretations and fidelity/proof requests bypass it. Similarity cannot accept a step or change the scenario vocabulary. Optional prose and structured rule views derive from the same supplied scenario; they add no facts or completed reasoning.

Proof scope

For Two Guards, Prolog checks every possible world with iterative deepening. Coq independently checks the generated Boolean theorem, satisfiable assumptions, graph consistency, door decoder, explicit choices and existential strategy witness. No admitted proofs are generated.

For named scenarios, Prolog searches a finite rule graph. Coq checks the derivation as a theorem conditional on those visible facts and rules. This does not recheck the arithmetic or temporal definitions in the problem-only Isabelle/HOL theories. Those require the native Isabelle build. Worked attempts are excluded from downloads and from the logical premises; they provide only non-authoritative hint guidance. Imported custom THY files are restricted to the supported declarative grammar; arbitrary HOL/ML is not executed.

Access and learning

The interface uses sans-serif reading text, keyboard controls, optional text and node views, adjustable guidance and saved notes. Browser zoom and reading tools can change the presentation. Guidance and access supports stay available at every difficulty; the optional timer does not score reasoning.

English is the supported interface language. The scenario vocabulary is bounded: interpretation errors and unsupported expressions are not judgments about ability. Checks establish translated statements under supplied rules; they do not independently assess every written reason, explanation quality or transfer. Reflections are personal learning records.

This is an evaluated feasibility prototype. WCAG 2.2 AA is the technical target; the evolving WCAG 3 draft is used for review, not a conformance claim. Physical assistive-technology, mobile and consented learner evaluation are still needed.

Storage

Sessions, drafts, reflections, settings, evidence and the optional fictional-example index use IndexedDB. The main Gemma model uses the origin-private file system. App files, proof libraries and optional encoder assets use Cache Storage. There are no accounts, analytics, learner uploads or inference API calls. Downloads contact the listed static hosts after consent; query encoding stays on device. Browser storage may be cleared or evicted; export personal work before changing device or origin.
