PROTOTYPE GUIDE · OCTOBER 2026

Reasoning, one step at a time

Thread is a private practice space for exploring arguments. I explain a thought, review its interpretation, check it against a scenario, then reflect. It is a research prototype; it does not grade my ability or establish facts about real people.

Start here

  1. Open Device setup in a browser with WebGPU. Read the device requirements and consent to download the local tools.
  2. Return to Thread. Open Preferences if I want larger text, more spacing, reduced motion, different guidance or a simpler workspace.
  3. Choose the guided archive tutorial. Read its short briefing and continue to thinking.
  4. Write one thought in my own words. Confirm the interpretation only when it matches. Revise a mismatch before verification.
  5. Explore the feedback, explain the next connection, and reflect when the scenario is complete.

There is no compulsory timer or reflection. I can pause, export, restart, or change support. English is the supported interface language; other input languages have not been validated.

Minimum system requirements

These requirements apply to the current browser/PWA edition with local Gemma, Prolog and Coq. No separately installed Python, Isabelle or Coq is needed.

  • Browser: JavaScript, browser workers, WebAssembly, Web Locks and WebGPU with a usable GPU adapter. The current Gemma runtime has no CPU-only fallback.
  • Secure address: HTTPS, or a trusted local preview such as http://127.0.0.1:8765/. Service workers must be permitted. A directly opened HTML file or ordinary HTTP LAN address cannot provide the full offline app.
  • Local storage: working IndexedDB, Cache Storage and OPFS (private browser file storage). Use the compatibility check to check writing and resuming.
  • Space: about 2.27 GB of remaining browser storage quota at the fresh-install check. Allow 3 GB or more as a practical budget, plus physical disk space for temporary files, updates and backups. This allowance is a recommendation, not a guaranteed peak-storage figure.
  • Working memory: enough available RAM and GPU memory to run the model and proof tools together. A numeric minimum has not been established. Download size and successful installation do not establish that inference will fit.
  • Connection: needed for the initial consented installation, about 2.17 GB of model and runtime payload, or 2.41 GB including the recommended encoder, plus the interface and transfer overhead. Once installed and cached, compatible devices can interpret and verify new thoughts without internet or an application server.
  • Input: keyboard, touch or equivalent accessible input. No camera, microphone or account is required.

Use a maintained browser with these capabilities. Chromium browsers have the strongest evidence so far. On iPhone/iPad, Safari 26 or later is needed for normally enabled WebGPU; Safari 18.7.3 does not meet this requirement. Safari 26 is an API availability threshold, not a guarantee of sufficient device memory. Android support also depends on browser, GPU and drivers. Run the current benchmark on the intended device before a presentation.

How the requirements were determined

Implementation and file sizes

The installer probes local file storage and requests a real WebGPU adapter before the large download. Model coordination requires Web Locks; local records, offline files and proof tools require the browser storage and worker capabilities listed above. Google's LiteRT-LM Web API describes this model/runtime as using WebGPU. WebKit's release notes establish Safari 26's WebGPU availability.

The pinned model is 2,008,432,640 bytes. The source runtime manifest contains 157,328,476 bytes, and the installer adds 100,000,000 bytes of headroom. With no existing model, that is 2,265,761,116 bytes, or about 2.27 GB. The website's rewritten assets can differ slightly; its current manifest and displayed installer requirement are authoritative. A partial existing model reduces the additional amount needed.

This requirement is compared with estimated quota minus current usage. The small interface and existing records already use some quota. Browser bookkeeping, temporary writes, other pages on the same origin and eviction mean file totals cannot establish an exact total-disk requirement. The 3 GB recommendation provides an allowance above the installation check. It is not derived from a low-storage stress test.

Benchmark evidence and its limits

The recorded pre-embedding baseline build passed 73 feature checks and 18 scripted journeys, including 43 meaning checks, with cache-only mode enabled and its local server stopped. The OS remained online. Earlier supplied OnePlus 11 and university-laptop reports each passed the then-current 45 checks online. These results do not validate the new optional encoder, certify the newer release or demonstrate phone airplane-mode operation.

The browser reported memory values of 8 or 16 GB. These came from an approximate browser API, not measurements of installed/free RAM or peak GPU memory. They cannot establish a minimum. More devices, measured memory use, repeated cold/warm runs and physical offline tests are needed to determine a numeric hardware floor. The source documentation contains the full requirements, calculation and report references.

Installation and offline use

The browser edition uses Gemma 4 E2B, LiteRT-LM, SWI-Prolog and the Coq 8.20.1 kernel. The browser model's QAT provenance is unconfirmed; this edition uses the approved E2B fallback. No cloud inference is used. Model and tools are fetched only after consent; small interface files can update when connected.

  1. Open Device setup, review the available quota and complete the local tools installation.
  2. Run the feature benchmark with real Gemma, then the scripted player journeys. Installation alone does not establish enough working memory.
  3. Use the browser's Install app or Add to Home Screen option. On iPhone/iPad, this is in Safari's Share menu.
  4. Enable cache-only mode in Device setup, then close and reopen the app.
  5. On a physical phone, turn on airplane mode. Submit, review and verify a new thought.

A cached opening screen alone does not demonstrate offline reasoning. Browser storage can be evicted, especially under storage pressure. Use a normal retained browser profile and export an attempt before an important demonstration. Private/incognito storage may disappear when the session closes. Unsupported WebGPU devices cannot run the current model locally; a separate native runtime remains planned.

Response architecture and future research

Gemma proposes a translation; my confirmation reviews its meaning; the compiler, Prolog and proof kernel check its stated support. Conditional reasoning is useful exploration and cannot silently establish facts. Exact roles, polarity and references are checked before a candidate enters my reasoning trail.

The next engineering experiments are source-linked interpretations, shorter typed outputs, compatible grammar-constrained decoding, incremental certificates, resident proof workers and paired fixed/lexical/semantic retrieval comparisons. Additional models and parallel inference need memory and battery measurements on mobile devices.

A hybrid diffusion model is a separate research direction: retain ordered blocks of reasoning while denoising bounded outputs within each block. It needs a compatible sampler, joint syntax constraints, training data, export support and the same fidelity/proof tests. Accepted reasoning must never be remasked or silently revised.

Google’s DiffusionGemma is a desktop research comparator, not a packaged mobile replacement for the current E2B model. The source documentation contains the option matrix and experiment gates. No diffusion runtime is included. The optional GLiNER 2.5 Multi pack records unverified wording proposals. Its strict argument checks failed, so the app retains full-source Gemma translation. Compact and encoder-assisted refinement are experimental lab variants. Existing fidelity checks, player review and proof gates remain; proposals establish no truth.

Mathematical, temporal, philosophical and real-case activities

The library contains six proof-method activities, two temporal puzzles, two philosophical puzzles, six representative Szemerédi proof routes, a DNA sample-identity activity based on the Pitchfork case and an evidence-review activity based on the official Stapel investigation. Sources and attribution appear in each relevant briefing.

Mathematics and philosophy use supplied-principle dependency models. They do not independently formalise arithmetic, dependent type theory or the full Szemerédi theorem. Temporal inspection evaluates the supplied infinite repeating trace; it is not a proof over every possible execution. Historical exercises separate published findings from teaching assumptions and do not invite new accusations about real people. Sensitive themes require a choice; neutral alternatives remain available.

English remains the gameplay language. The model may exceed available mobile working memory; a universal RAM minimum and speed benefit have not been established. I can keep Fixed examples, choose Dynamic examples · words only without another model, or try Dynamic examples · EmbeddingGemma + words. These are experimental ways to choose an instructional example for Gemma. Faster or more accurate interpretation is not guaranteed.

Install only if I want semantic selection

  2. Review the extra download: 241 MB for EmbeddingGemma and its CPU runtime, under the listed model terms and licenses. What changes, and what is still checked

The example library contains 84 original English examples across 28 reasoning approaches and three script profiles. It is agent-reviewed; human review is pending. Profiles describe examples, not my ability. The library includes mistaken arguments so that interpretation preserves what was said. It supplies no facts or accepted steps to my scenario.

At most one optional example changes in eligible named-scenario prompts. The fixed negation and unsupported-concept examples stay in place. Two Guards, exact/narrowed interpretations and fidelity/proof checks bypass this selection. My wording, scenario facts, interpretation review and formal verification remain unchanged. If no suitable example or encoder is available, the fixed prompt is used.

Only my current thought needs encoding during semantic selection; the 84 examples are supplied as a precomputed index. An incompatible index uses the fixed route rather than starting a long preparation job during my turn. A format error or a detected omission of explicit supporting-reason roles can trigger a bounded retry with fixed examples. Persistent omissions ask for clarification; the system does not invent the missing reasons.

Device and privacy limits

Embedding runs locally on the CPU in a browser worker and needs extra working memory. It does not remove Gemma's WebGPU requirement. The encoder processes up to 128 tokens per thought; longer thoughts use the fixed route. A validated physical iPhone/Android result for this optional stack is still needed. The Example selection · fixed, words, EmbeddingGemma benchmark helps compare modes on my device.

Weights download from Hugging Face after my explicit choice; thought text is not sent there. The index contains fictional examples, not my reflections. Complete setup before enabling cache-only mode or disconnecting. Browser site-data deletion also removes attempts and other installed tools; export wanted records first.

Gameplay and what verification means

A supplied fact belongs to the scenario. An assumption adds a condition. A claim states a conclusion. A warrant connects evidence to that conclusion. A counterexample shows a case where a claim fails.

Gemma interprets language; it does not decide whether an argument is correct. I check its meaning before confirmation. Prolog searches the finite scenario using iterative deepening depth-first search. Positive deductions must then pass the independent Coq kernel. A goal check follows each verification attempt.

Two Guards requires both a question that determines safety and an explicit safe choice strategy. In other scenarios, certificates establish deductions within the displayed finite rules. They do not establish the truth, fairness or completeness of those rules in the real world. Explanation quality still needs my review, or discussion with a teacher or willing peer.

Inspect logic & code shows the visited graph, a read-only node view, Prolog and proof sources. Isabelle/HOL is an inspectable reference in this browser edition; it is not executed. Background predictions are private, unvisited cache entries and are excluded from my trail.

If a tool fails, my draft remains available. A failed translation or unavailable verifier is not evidence of a failed argument. Streaming status never accepts an incomplete interpretation.

Scenarios, themes and meaningful choices

The library includes Two Guards, three murder investigations with different complexity, and other logic scenarios. The tutorial introduces the review loop. The Evidence Review adds seeded subject, setting and challenge choices across undergraduate disciplines and researcher skills.

Choose a neutral context if allegations or investigation themes are unwanted. Subjects and settings do not profile my identity or diagnosis. Guidance is independent of difficulty and can change during play.

The three-stage review offers a small evidence budget. My purchases change the information available in later stages. I record an optional reason for each choice, receive a brief reflection between stages, then a fuller debrief. An appropriately limited conclusion can be valid when information is missing.

Current story branches are authored and finite. Seeds, choices and my reasoning create variation, but the system does not generate an unrestricted world. Keeping the same version, seed, difficulty and choice path reproduces a case; changing subject or setting can support transfer practice.

Accessibility, reading and personalisation

Preferences groups controls into reading, pace/support and workspace options. Sans serif fonts, larger text, wider spacing, reduced motion, focus view, direct wording and optional guidance support different preferences. No single font or layout suits every dyslexic or neurodivergent learner.

I can use browser zoom and keyboard navigation. The graph has a text representation. Hide scenario information focuses the thinking workspace; show it again whenever useful. Processing pauses the optional timer. Background preparation can be disabled to reduce optional work and battery use; future steps may take longer.

Reading settings also apply to these help, setup, notices and demonstration pages on reopening. Reset preferences restores defaults without deleting my attempts. Accessibility checks guide development; they are not a claim of universal usability or WCAG certification. Screen-reader and physical-device evaluations with users are still needed.

Reflection and argumentation practice

The debrief distinguishes exploration from the direct route. Trying an unsuccessful approach can help identify a boundary or eliminate an alternative. Optional reflection prompts ask what justified my conclusion, what changed, which assumptions mattered and what I will try elsewhere.

The reasoning toolkit offers critical questions about evidence, inference, sources, scope, alternatives and transfer. Fallacy names are optional prompts for examination, not automatic diagnoses of a person's reasoning. A formal proof does not by itself show deep comprehension or transfer.

Practice a new surface context without copying the earlier words. Explain why a connecting rule applies, identify a counterexample when one condition changes, and compare the strength of the resulting conclusion. I can discuss a voluntarily selected excerpt with a willing peer; Thread currently provides solo practice, not a social classroom.

Social practice, belonging and voluntary sharing

I can choose one idea that feels useful or interesting, explain its evidence and limits, and invite one fair question from a willing peer. My partner restates my meaning before challenging it; we can exchange roles or stop. I can rehearse both roles alone. Agreement, likes and speed are not measures of reasoning quality.

A setting may feel familiar, surprising or uncomfortable to different people. I choose the context without being assigned an identity or ability. Comparing the same seed and difficulty across settings can reveal what transfers and which assumptions need revisiting.

I share only deliberately selected text. Full exports can include private reflections. Thread has no sharing feed or messaging service. Peer invitations, shared cases, turn taking and moderation belong to the planned separate social-play app.

Create or import a scenario

Choose scenario includes a small builder for plain-language statements, facts, rules and a goal. Review the generated case before playing. Downloadable THY files illustrate the supported finite format.

Imported THY is parsed as data. Arbitrary Isabelle programs, tactics and ML code are not executed. The section after Draft Attempt is excluded from public scenario facts and downloads; author material is never a trusted assertion. Unsupported theories require adaptation to the template.

Generated scenarios carry version and seed metadata. Editing their canonical source while retaining that metadata is rejected; create an ordinary custom theory if changing the logical model. Authors should check reachability, unintended shortcuts, wording, content themes and what their rules assume. Automated import does not replace subject expertise.

Privacy, backups and deleting local data

Attempts, drafts, reflections, settings and benchmark reports stay in this browser's local storage. Model files use private browser file storage; runtimes use browser caches. There is no account, analytics upload or cloud language processing in this edition.

Local storage is not encrypted by Thread. Anyone with access to the browser profile, extensions or the device may be able to access it. Other pages or scripts on the same website origin can share access: the /Experiment path is not a security boundary. Avoid entering sensitive research records or identifiable case details.

Use Export reasoning record for a JSON backup, or Export readable reasoning notes for text. Restoring JSON creates a new attempt and rechecks accepted claims. Keep exports private if they contain personal reflections. Restart creates a fresh attempt; it does not erase the earlier record.

To remove local data, use the browser's site-data controls. This can remove other data for the same website, not just Thread. Save wanted exports first. Deleting site data also removes installed tools and can require another large download. Separate per-attempt deletion controls and an isolated hosting origin are planned.

Benchmarking and troubleshooting

Device setup offers feature coverage and 18 fixed scripted journeys across beginner, experienced and expert response scripts. These labels describe scripts, not measured learner expertise. Procedural generation is checked in feature coverage and is deliberately excluded from those player simulations.

Record the device, browser, power condition, build and cold/warm state. Compare at least three runs under similar conditions. Tool totals may overlap within elapsed time; iframe UI work has separate telemetry. Keep failures and blocked checks in the evidence.

  • Interpretation mismatch: revise or clarify before confirming. The model can make semantic errors even when JSON is valid.
  • Incomplete interpretation: one bounded format retry runs automatically. If it fails, retry or shorten one case; the original draft remains.
  • Model busy: finish or cancel work in another Thread tab.
  • Proof unavailable: use Check / retry proof tools in Device setup.
  • Integrity error: verify the complete publication was copied byte-for-byte, including .gitattributes. Repair the installation while connected. Never bypass the hash check.
  • Blank or broken local file: use the HTTPS site or the local static preview URL, not a file:// address.

Passing the benchmark establishes only the covered cases on that device/build. It does not prove there are no remaining defects, assess learning gains, or replace physical mobile and assistive-technology checks.

Roadmap and future solutions

Publication priorities after this demonstration are learner-led accessibility studies, interpretation-fidelity evaluation, a transfer and reflection rubric, broader physical-device measurements, and maintainable signed release/update processes.

Planned improvements include validated multilingual content, richer argument maps and editing, simpler authoring with Quarto extraction, more flexible stage budgets and branching, local data management, and native mobile/desktop packages that include their dependencies. Browser builds currently use Coq; a newer Rocq or Isabelle option needs compatible runtime and certificate testing.

A separate social-play app is proposed for peer-to-peer argumentation. It should use mutual invitations, explicit sharing of selected arguments, accessible turn taking, disagreement and appeal paths, moderation, and a solo exit. Private reflections and transcripts should not transfer by default. Networking may require rendezvous or relay services and cannot be promised to work offline between arbitrary devices.

These are planned features. The current PWA is solo and does not include accounts, peer networking, app-store packages or a fully bundled executable.

Research and technical scope

The learning design draws on Manchester Library's argument guidance, critical analysis resources, CAST UDL guidelines and Salmon's five-stage model. Access and orientation are implemented; full online socialisation requires human participation. External research links need a connection; the guidance in Thread remains local.

See versions, licenses and proof scope. The source distribution includes technical documentation, a HE-Tech requirements mapping, the SECTIONS review and dated benchmark evidence. Educational effectiveness and institutional suitability remain subjects for evaluation.

Optional local audio

Use Device setup to consent to a 162 MB speech pack. Whisper Tiny turns a recording of up to 30 seconds into an editable draft. Review it, then choose Add transcript to my thought; nothing is submitted automatically. Audio is not saved or uploaded.

Briefings can be narrated with a local device voice, or Kokoro when installed and no local voice is available. Audio is off by default and begins only after I enable it and interact. Installing the speech pack does not enable playback. Use Mute audio or Accessibility → Sound & narration to control narration, cues, music, volume and speed. Screen-reader users can turn narration off to avoid overlapping speech.

Gemma’s installed LiteRT web export accepts text only. A separate speech benchmark measures synthetic Kokoro-to-Whisper processing; it does not establish microphone or accent accuracy. Physical-device evaluation remains necessary.

Reasoning and task formats

I can refer to an exact observation as Fact F1 and to a connecting rule as by Rule 1. Cited rules appear in interpretation review and the debrief. When I cite a rule, the check uses that rule to justify the connection; it cannot silently borrow a different rule. Unknown identifiers need clarification.

The first visit opens the archive tutorial. Optional tips introduce one control at a time. Enter shares a thought by default; Shift+Enter adds a line. Preferences can switch this off.

Checks distinguish conditional connections, unresolved premises and established conclusions. Completion requires grounded reasoning from my stated premises and established earlier steps. The introductory Identify a solution format is explicitly an answer check only. Older attempts retain their trail but must have completion checked under the new contract.

The generator separates task format, challenge, guidance, subject pathway and aesthetic context. Eight formats reuse bounded evidence-review templates. The 79 distinct subject-filter labels are an offline snapshot of Manchester’s 2026 catalogue, grouped by Thread; they are not 79 separately authored curricula or a degree count. Researcher skills is a separate pathway. Misconduct and criminal-investigation contexts require explicit consent. The subject-matched setting maps researcher skills and criminology to those themes; neutral settings remain available.

Full benchmark runs features, journeys, wording and retrieval sequentially. Tool totals include waiting and may overlap. Speech, real-device airplane mode, audible sound, accents and assistive technology still require their own checks.

New review features

Build and revise a case in five phases

Choose structure and guidance, inspect the graph transformation, fill fictional narrative variables, optionally add contextual notes, then review the preview. Each phase shows its current state and can be revised independently. Structure, transformation and narrative seeds control different changes; the graph check preserves the required solution route.

Unicode interests such as “Dungeons & Dragons” are supported. Local Gemma can ask up to three optional contextual questions and suggest editable fictional names, places and exposition. These personalise the presentation without adding logical facts. Optional Wikipedia background search shows the exact combined subject, task and context query before I consent and press the search button. My interest, fictional names, thoughts and notes are not sent. Sources remain contextual notes, never formal premises. Generation works without research or a connection.

Paired examples, competing arguments and solo debate

Apply and Analysis offer a separate example selected from the same subject catalogue. The structure seed selects one of four evidence practices. Apply names the method; Analysis asks me to infer it. Completion requires identifying that method and applying it in both examples. Evaluate varies the relationship between two proposed arguments; their claims are not facts. Debate ties bounded opponent replies to my established objections and the current stage.

The finite proof checks that I connect the supplied conditions and conclusions. It does not independently assess the depth of my explanation or disciplinary expertise. Discussing transfer and justification remains useful.

Graph references, interchange and possible worlds

The single Reasoning support area is a right column on wide screens and stacks on small screens. Its graph tools can inspect EmbeddingGemma vectors, export AIF/xAIF JSON, and query all or at least one admissible Boolean/Horn world. Choose scenario knowledge or my established knowledge. These diagnostics add no accepted reasoning. Only grounded steps and connected premises constrain my knowledge; hypotheses retain uncertainty.

Each verification step has separately collapsed scenario, learner, explicit-support and completion checks under Inspect logic & code. Positive checks include Prolog and kernel certificates. A broader proof cannot repair missing explicit support. Isabelle source is a reference in the browser. The world model is a supported finite projection, not arbitrary HOL or general Kripke semantics. AIF exports include my selected reasoning text; review before sharing.
